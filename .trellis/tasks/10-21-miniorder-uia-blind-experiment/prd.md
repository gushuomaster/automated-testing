# MiniOrder 首轮 UIA 黑盒自主测试实验

## 目标与用户价值

验证在只提供中文业务需求、匿名可运行软件和 Windows UIA/键盘工具时，独立 Codex 测试上下文能否自主设计测试、执行 GUI 测试、判断结果并发现和复现受控缺陷。样本就绪和评估方冒烟仅作为前置条件，不计入自主测试成绩。

## 已确认事实

- MiniOrder 有一个满足规格的 Baseline、一个错误接受数量 0 的 VariantA，以及一个错误使用加法计算金额的 VariantB。
- 三个可执行文件的可见产品元数据和 UIA 身份一致，普通界面不显示真实版本身份。
- 中文需求独立描述输入校验、金额计算、编号、状态、查询和持久化，没有植入缺陷答案。
- Computer Use 可读取 UIA 树、设置值和发送键盘输入；截图通道当前超时，元素索引点击可能缺少几何。
- Git 仓库没有首个提交，`HEAD` 不存在；本轮以逐文件清单、SHA-256、工作区状态和工具环境冻结基线。

## 需求

### R1. 基线冻结

- 记录工作区状态、源码/需求清单哈希、三个 EXE 哈希、种子哈希、Windows、PowerShell、.NET、OpenSpec、Trellis、Computer Use 和 Codex 线程配置。
- 匿名映射、评分规则和预算必须在正式报告产生前固定。

### R2. 信息隔离

- 预演和三个正式版本分别使用新建、无历史继承的 projectless Codex 线程。
- 每个正式线程只获得中文需求文本、窗口标题、允许工具和统一协议；不获得仓库项目、源码路径、真实版本身份、缺陷清单、契约矩阵、历史诊断或其他线程报告。
- 每个版本使用匿名路径和独立数据目录，按相同种子重置；正式版本顺序执行，避免同时窗口串扰。
- 当前环境不提供 OS 级文件系统沙箱，隔离强度如实标记为“独立会话 + 最小提示 + 匿名路径 + 操作约束”，不是安全边界。

### R3. 固定协议

- 每版本预算为最多 25 分钟、60 次 GUI 输入动作、单一工具动作最多重试 2 次。
- 允许 UIA 文本、焦点、控件值和键盘操作；不允许终端、源码、反编译、内部数据文件、调试接口、数据库或内部 API。
- 测试方必须在首次业务操作前输出首批测试设计，并在最终报告保留调整记录。
- 测试结论使用 PASS、FAIL、INDETERMINATE；执行状态单独记录。
- 人工提示、恢复或接管逐项计数；评估方只负责重置、启动和关闭程序。

### R4. 预演与正式盲测

- 使用独立预演线程验证“需求理解 → 设计 → GUI 执行 → 判断 → 复现 → 报告”闭环；预演不计分，数据和上下文不进入正式实验。
- 三个匿名版本各用独立正式线程和数据目录完成盲测，保留原始报告和线程标识。
- 测试报告锁定后才由评估方揭示匿名映射并评分，不改写原始报告。

### R5. 评估

- 分别统计需求设计覆盖、可判定执行覆盖、已知缺陷检出、漏检、误报、独立复现和人工介入。
- 区分测试设计、GUI 执行、结果判断与环境限制。
- 不把设计用例计为执行通过，不把工具失败计为产品缺陷，不把一次成功外推为通用可靠性。

## 验收标准

- [x] AC1：基线、协议、匿名映射和工具环境在正式执行前冻结并可复核。
- [x] AC2：预演由独立上下文完成，流程问题被记录，预演数据未复用。
- [x] AC3：三个正式匿名版本由互相独立且不继承实现知识的上下文完成，原始报告已锁定。
- [x] AC4：每个正式报告含首批设计、变更记录、执行证据、PASS/FAIL/INDETERMINATE、执行状态和缺陷复现信息。
- [x] AC5：评估在报告锁定后完成，明确分子、分母、误报、漏检、人工介入和失败归因。
- [x] AC6：最终结论严格区分样本就绪、预演完成、正式盲测完成和能力支持范围。

## 不在范围内

- 修改 MiniOrder 业务功能或中文需求。
- 建设通用测试平台、引入服务/Runtime/大型依赖。
- 证明视觉路径、其他 Windows C/S 软件、多 DPI、RDP 或无人值守场景已适配。
- 自动提交、推送、合并、发布或归档现有 MiniOrder OpenSpec 变更。
