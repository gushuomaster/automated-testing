# MiniOrder 首轮 UIA 黑盒自主测试实验设计

## 角色与信任边界

- 当前会话是实验组织者和评估方，可读取真值、源码和既有证据。
- 预演线程只验证流程，不计分。
- 三个正式测试线程互相独立，采用 `create_thread` 的 projectless 本地任务且不继承本会话历史。
- OS 账户和主机仍共享，无法形成强制文件系统安全沙箱；通过匿名 staging、最小提示、禁止终端/文件读取和线程审计降低泄露风险。

## 目录

```text
evaluation/miniorder/experiments/round-01/
  protocol.md
  baseline.md
  isolation.md
  final-evaluation.md
artifacts/miniorder/experiments/round-01/
  baseline/
  rehearsal/
  formal/target-01..03/
  raw-reports/
  diagnostics/
```

运行目录和原始证据属于生成产物；最终可审阅报告位于 `evaluation/`。

## 匿名化与运行

评估方在正式执行前随机排列三个私有发行包，将其复制为 `target-01`、`target-02`、`target-03`。每个目录只含 `MiniOrder.exe`，进程路径和 UIA 元数据只暴露匿名编号。每轮使用同一固定种子重置到独立数据目录，评估方预先启动窗口，测试线程不接触启动命令或真实来源路径。

## 报告锁定

每个线程的最终 Markdown 原样保存到 `artifacts/.../raw-reports/`，同时记录线程 ID、开始/结束时间和人工消息。保存后计算 SHA-256；之后才读取私有映射评分。任何评估注释写入独立文件，不回写原始报告。

## 评分口径

每版本 100 分：首批设计质量 20、可判定执行覆盖 25、证据与状态区分 20、结论正确性 20、缺陷复现/无缺陷判断 10、自主性 5。总体另外报告：

- 需求设计覆盖率 = 已有合格设计的需求组 / 6 个需求组。
- 可判定执行覆盖率 = 至少一项测试得到 PASS 或 FAIL 的需求组 / 6 个需求组。
- 已知缺陷检出率 = 正确报告并复现的植入缺陷 / 2。
- 误报数 = 经真值与独立复核不成立的已确认缺陷数。
- 人工介入数 = 评估方在初始提示之后发送的提示、恢复或接管次数。

六个需求组固定为：录入字段与初始状态、文本校验、数量/单价校验与金额、保存/编号/状态、查询筛选与完整显示、持久化与数据目录隔离。

## 风险

- 截图不可用：本轮只评价 UIA 路径，并记录视觉证据缺失。
- UIA 首次切页可能返回部分树：允许重新观察，计为工具恢复而非产品缺陷。
- projectless 线程仍运行在同一主机：报告隔离限制，不声称强安全沙箱。
- 无 Git HEAD：使用清单哈希冻结，不把未提交工作区描述为提交版本。
