# 第二阶段软件探索能力验证设计

## 设计目标

用现有 S1 需求基线和 Computer Use/UIA 完成最小、可审计的软件探索实验。此次不实现新的产品模块，先验证输入输出契约、隔离办法和能力门槛是否成立。

## 运行边界

```text
评估方
  |- 冻结 MiniOrder Baseline、种子、环境和 UI 真值映射
  |- 准备两套输入
  |    |- S2-A：人工核验需求集合
  |    `- S2-B：S1 真实 requirement-baseline/v1
  |- 独立 UIA 健康检查
  `- 报告锁定后评分

独立测试 Agent A / B
  需求输入 + 匿名窗口 + 通用工具规范
      -> 需求驱动探索计划
      -> UIA 被动清单
      -> 非破坏性状态遍历
      -> 需求到入口/路径/状态映射
      -> 原始报告
```

## 复用与不复用

- 复用 S1 `requirement-baseline/v1`、来源定位和歧义信息，不重新解析文档。
- 复用 `computer-use` 技能与 `mcp__node_repl__js + @oai/sky`，不封装新的 UIA Driver。
- 复用 MiniOrder Baseline、固定种子、数据目录隔离与历史 UIA 事实作为评估侧准备依据。
- Trellis 管理任务与规划，实验目录保存协议和评估；它们不充当探索引擎。
- 不复用 round-01/02 的测试 Agent 报告作为 S2 答案，不向正式探索 Agent 提供旧路径和元素清单。

## 输入设计

### S2-A：核验输入

评估方从 MiniOrder 中文需求整理 UI 探索所需的需求集合，保留需求标识、原文位置、行为描述和已知歧义。只做拆分与去重，不提供控件名称、入口、操作路径或真值答案。

### S2-B：真实上游输入

从已锁定校准运行读取 `requirement-baseline-initial.json`，生成只包含正式需求、来源定位和歧义的中性交付包。去除运行日志、模型响应、评估信息和本机仓库绝对路径；语义内容和需求标识保持不变，并记录转换清单及哈希。

## 输出契约

原始报告至少包含：

- 运行标识、输入哈希、窗口身份和工具版本；
- 首批探索计划及后续变更；
- 窗口/页面/控件/状态清单；
- 按时间排序的观察和动作轨迹；
- 每条需求的映射状态、入口、路径、可观察状态、UIA 证据和置信度；
- 不可观察、不可达、未知和工具受限项；
- 副作用、恢复、重试、人工介入和预算使用；
- 不含业务 PASS/FAIL 或缺陷结论的最终摘要。

## 真值与评分

评估真值以“需求 -> UI 目标/状态/路径/可观察性分类”为主，不要求测试 Agent 逐字复现 AutomationId。语义等价映射可判正确，但必须由真实 UIA 元素或界面行为支持。

- 入口召回率：正确找到的关键功能入口 / 真值关键入口。
- 映射召回率：正确映射的 UI 相关需求 / 真值 UI 相关需求。
- 映射精确率：正确映射 / Agent 报告的正式映射。
- 路径可复现率：评估方可按报告复现的路径 / 报告路径。
- 分类正确率：正确区分非 GUI、不可达、工具阻塞和证据不足的项目 / 对应已裁决项目。
- 无依据控件比例：不存在或无证据控件 / Agent 报告控件。

同一需求可对应多个控件，一个控件也可支持多条需求。重复描述不增加分子；部分映射单独记录，不自动按完整命中计分。评分细则在正式运行前冻结。

## 隔离与安全

- 健康检查、S2-A、S2-B 使用三个独立、无历史继承的测试上下文和独立初始数据目录。
- 测试 Agent 不获得终端、文件系统或评估目录访问授权；评估方负责启动、关闭和恢复窗口。
- 软件路径、数据目录和提示使用中性名称，不包含 Baseline、Variant、defect、truth 或历史轮次信息。
- 允许页签切换、聚焦、展开只读或可恢复控件；瞬时输入仅在不保存的情况下使用并清除。
- 任何可能持久化的命令都不在 S2 允许动作内。发现无法判断的副作用风险时停止而不是试探。
- 当前隔离是认知与流程隔离，不声明为 OS 级安全沙箱。

## 可比性与结论

S2-A 与 S2-B 使用同一软件、工具和预算，但输入形态不同；两者用于定位连接损失，不合并为单一泛化分数。MiniOrder 已参与旧实验，因此即使两次都通过，也只证明受控样本上的软件探索和 S1 -> S2 连接可运行。

## 回滚与阻塞

- 健康检查失败：保留诊断证据，停止正式运行，不修改执行器或 MiniOrder。
- 非破坏性动作产生持久化变化：立即停止，保留证据，重置独立数据目录后评估协议缺陷；已受影响运行不计分。
- 工具版本或实质语义变化：重新冻结环境并说明不可比性。
- 输入或真值在正式报告锁定前有实质变更：废弃未开始的冻结包并生成新版本；已经开始的运行保持原样，不混用成绩。
