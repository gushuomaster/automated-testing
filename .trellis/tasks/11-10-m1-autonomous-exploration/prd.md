# M1 自主探索与缺陷发现

## 目的

回答"只给需求文档和软件，AI 能否自主测试并发现真实缺陷"。M0 已证明按明确指令操作陌生软件是可靠的（72 次运行，0 次虚假成功）；M1 去掉指令，考核探索、用例设计和缺陷判定。

## 输入（Agent 可见）

- 被测软件：KeePassXC 2.7.6，M1 专用种子库（根群组和子群组都有条目，含一个 TOTP 条目）。
- 需求文档：KeePassXC 用户手册节选（`guide/*.adoc`：界面、数据库操作、快捷键、密码生成器）。
- 测试目标：一句话说明，不提示任何缺陷。

## 真值（Agent 不可见）

2.7.6 中存在、之后版本修复的历史缺陷。**只有经组织方在 2.7.6 上脚本复现确认的才计入**。候选：

| 编号 | 缺陷 | 修复版本 |
|---|---|---|
| #9765 | 安全设置页 Tab 顺序与视觉顺序不一致 | 2.7.9 / 2.8.0 |
| PR 10667 | 条目编辑点"应用"后按钮仍可用 | 2.7.8 |
| #9865 | 搜索后默认选中的不是列表第一条 | 2.7.7 |
| #9996 | 隐藏 TOTP 设置在重启后的首个条目上不生效 | 2.8.0 |

## 流程（框架代码编排）

1. **规划**（无 GUI）：读手册，产出若干测试章程（charter：功能区 + 关注点 + 预算）。
2. **章程执行**：每个章程是一次独立的 Agent 会话（新上下文，携带前序章程的界面笔记），复用 M0 执行服务。新增工具：`note`（记录界面/功能发现）、`report_defect`（标题、复现步骤、期望（引用手册或通用准则）、实际、严重度、证据为当时的观察截图编号）。
3. **汇总**：去重，产出缺陷报告与覆盖的功能列表。

框架强制：每章程动作/时间预算、总预算、每次 report_defect 自动附当时截图。

## 度量

- 已知缺陷召回：报告与真值匹配（人工判定，记录依据）。
- 报告精确率：每条报告判为 真实缺陷（已知/新发现）/ 非缺陷 / 无法判定；新发现的需组织方复现。
- 覆盖：章程覆盖的手册功能点。
- 成本：动作、耗时、token、费用。
