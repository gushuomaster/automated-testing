# M0 GUI 执行可靠性基线

## 目的

回答"AI 能否稳定操作一个陌生 Windows 桌面软件完成给定任务"。这是自主测试的前提：执行不可靠，后续的探索、用例、判定都无意义。本里程碑只考执行，不考需求理解与缺陷判定。

## 范围

1. **执行服务**（`src/testing_platform/autotest/desktop/`）：独立子进程，JSON 行协议；观察 = UIA 控件列表 + 截图（叠加控件编号）；动作 = 元素点击、坐标点击、文本输入、按键、滚动、UIA Invoke/SetValue。调用超时由客户端强制，超时重启服务。动作前校验目标进程在前台、点击点属于目标进程。
2. **模型适配**（`autotest/model.py`）：Anthropic Messages API，经 `ANTHROPIC_BASE_URL`；默认 `claude-opus-5-5`，可切换。后续本地模型通过同一接口替换。
3. **Agent 循环**（`autotest/agent.py`）：自定义工具；每次动作后自动回传新观察；框架强制动作数/时间/模型调用预算；每步写 JSONL 与截图。
4. **基准**（`benchmarks/keepassxc-m0/`）：KeePassXC 2.7.6，10 项任务，每项从同一种子库重置启动；结果由 `keepassxc-cli export` XML 或配置文件确定性校验，Agent 看不到校验规则。
5. **度量**：完成率（校验通过）、Agent 自报成功但校验失败的次数（虚假成功）、动作数、耗时、token。

## 不做

需求理解、用例生成、缺陷判定、虚拟机隔离（M1 再迁移）、本地模型（无可用服务）。

## 验收

- 单元测试覆盖纯逻辑（预算、工具参数校验、XML 校验器、观察格式化、客户端超时）。
- 真实运行 10 项任务各 1 次，产出 summary；完成率不设门槛，作为基线如实报告。
