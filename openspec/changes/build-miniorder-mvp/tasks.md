# 实施任务

## 1. Solution 与领域契约

- [x] 1.1 在 `samples/MiniOrder` 中创建面向 .NET 8 的 Core、App 和 Verification 项目；首次 restore 后，验证 `dotnet build samples/MiniOrder/MiniOrder.slnx --configuration Release --no-restore` 在 warnings-as-errors 条件下成功。
- [x] 1.2 实现订单记录、校验结果、金额计算器、编号生成器和服务契约；使用不依赖第三方测试框架的 Verification 项目验证有效输入及所有已定义边界。
- [x] 1.3 实现带 schema 校验和原子替换的 UTF-8 JSON 持久化；在 Verification 项目中验证保存/重新加载往返一致、损坏数据处理和数据目录隔离。

## 2. Windows 桌面工作流

- [x] 2.1 实现基于标准控件的 WinForms 外壳和“新建订单”页签，设置稳定且中性的可访问名称和确定性 Tab 顺序；验证 UIA 能观察每个标签、可编辑字段、只读金额、命令和状态消息。
- [x] 2.2 将实时金额计算、行内校验、焦点管理、清空和保存行为连接到 Core 服务；通过 Core 检查和 GUI 冒烟验证确认有效订单只保存一次、无效输入不保存任何订单。
- [x] 2.3 实现“查询订单”页签、关键字/状态筛选、完整的只读结果表格和结果数量；验证已保存订单可被查询，且重启应用后所有显示值保持不变。

## 3. 受控版本与契约矩阵

- [x] 3.1 增加经过校验的 `MiniOrderVariant` 构建属性，以及 `Baseline`、`VariantA`、`VariantB` 的编译期行为策略；验证缺少版本值或使用不支持的版本值时发行构建失败。
- [x] 3.2 在 Verification 项目中增加三版本契约矩阵；验证 `Baseline` 没有失败，`VariantA` 只出现数量 0 契约失败，`VariantB` 只出现 `3 × 12.50` 金额契约失败。
- [x] 3.3 使用相同的可见产品元数据和中性可执行文件名发布全部版本；验证二进制校验和不同，但 UIA 树标签、窗口标题和版本文本一致。

## 4. 可重复样本与黑盒边界

- [x] 4.1 增加固定种子数据和仅供评估方使用、以显式数据目录为目标的重置命令；验证连续两次重置产生相同 SHA-256，并清除上一轮运行新增的订单。
- [x] 4.2 编写独立中文需求文档 `docs/miniorder/MiniOrder-Requirements.md`；验证它覆盖所有订单管理需求，且不提及实现方式、版本身份、植入缺陷输入或预期缺陷结果。
- [x] 4.3 增加私有缺陷清单和评估方操作手册；验证每个缺陷映射到一条需求，且操作手册记录干净启动、重置、证据采集和运行后清理方法。
- [x] 4.4 增加仅向 `artifacts/miniorder` 写入的构建脚本和中性 staging 脚本；通过 allowlist 验证 staging 后的 `blackbox-run` 目录不含源码、PDB、脚本、Ground Truth、验证工具或泄露版本身份的名称。
