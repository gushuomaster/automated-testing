# 变更提案

## 为什么要做

项目需要一个小型、确定性的 Windows C/S 应用，用来验证 AI 能否根据需求推导测试、操作陌生桌面界面，并区分软件缺陷与执行器故障。当前候选矢量地图软件缺少独立业务判定依据、可控缺陷和已验证的状态重置机制，因此不适合作为第一阶段基准。

## 变更内容

- 新增名为 MiniOrder 的 Windows 桌面样本，包含订单创建、输入校验、金额计算、持久化、查询和状态显示。
- 新增独立的黑盒需求文档，只定义可观察行为，不暴露实现细节或植入缺陷。
- 生成一个正确基线版本和两个分别植入缺陷的版本；三个版本具有相同的可见身份和操作流程。
- 新增确定性的种子数据、仅供评估方使用的重置入口和中性命名的交付包，使每轮实验都能从相同状态开始，且不会泄露所选版本。
- 新增业务核心自动验证、Windows GUI 冒烟验证，以及两个缺陷版本的定向检出验证。
- MiniOrder 与未来的自主测试平台保持独立；本变更不引入通用 Agent、规划器、执行器或报告框架。

## 能力范围

### 新增能力

- `order-management`：定义 MiniOrder 创建、校验、计算、保存、查询和显示订单时的可观察行为。
- `black-box-experiment-fixture`：定义可重复黑盒实验所需的基线/缺陷构建、测试状态重置、中性交付包和仅评估方可见的 Ground Truth。

### 修改能力

无。

## 影响范围

- 在本仓库新增独立的 Windows 桌面样本及其构建、验证资产。
- 新增黑盒需求文档和仅供评估方使用的实验元数据，并明确交付隔离边界。
- 使用本机已安装的 .NET Windows Desktop 工具链，不依赖服务端、数据库服务或第三方运行时。
- 不修改 `D:\project\agent` 下已有的 Agent 项目或 CUA 验证项目。
