# 规格增量：订单管理

## Purpose

本规格定义 MiniOrder Windows 桌面应用的可观察订单流程，用于评估由需求驱动的黑盒自主测试能力。

## ADDED Requirements

### Requirement: 订单录入字段
MiniOrder MUST（必须）提供可编辑的客户名称、商品名称、数量和单价字段，以及只读的订单金额字段。

#### Scenario: 空白的新建订单表单
- **WHEN** 用户打开新建订单页面
- **THEN** 所有可编辑字段均为空，订单金额不显示任何计算结果

### Requirement: 必填文本校验
客户名称和商品名称去除首尾空白后 MUST（必须）有值，且每个字段 MUST（必须）不超过 50 个字符。

#### Scenario: 必填字段为空
- **WHEN** 用户在客户名称或商品名称为空或仅包含空白字符时尝试保存
- **THEN** MiniOrder 拒绝保存、指出无效字段，并且不创建订单

#### Scenario: 文本超过最大长度
- **WHEN** 用户使用超过 50 个字符的客户名称或商品名称尝试保存
- **THEN** MiniOrder 拒绝保存、指出无效字段，并且不创建订单

### Requirement: 数量校验
数量 MUST（必须）是 1～999（含边界）的整数。

#### Scenario: 数量处于有效边界
- **WHEN** 用户输入数量 1 或 999，且其他字段均有效
- **THEN** MiniOrder 将该数量判定为有效

#### Scenario: 数量为零或负数
- **WHEN** 用户使用数量 0 或负数尝试保存
- **THEN** MiniOrder 拒绝保存、提示允许的数量范围，并且不创建订单

#### Scenario: 数量超过最大值
- **WHEN** 用户使用数量 1000 或更大值尝试保存
- **THEN** MiniOrder 拒绝保存、提示允许的数量范围，并且不创建订单

#### Scenario: 数量不是整数
- **WHEN** 用户使用小数或非数字数量尝试保存
- **THEN** MiniOrder 拒绝保存、提示数量必须是整数，并且不创建订单

### Requirement: 单价校验
单价 MUST（必须）是 0.01～999999.99（含边界）的十进制金额，且小数位不超过两位。

#### Scenario: 单价处于有效边界
- **WHEN** 用户输入单价 0.01 或 999999.99，且其他字段均有效
- **THEN** MiniOrder 将该单价判定为有效

#### Scenario: 单价超出范围
- **WHEN** 用户使用单价 0 或大于 999999.99 的金额尝试保存
- **THEN** MiniOrder 拒绝保存、提示允许的单价范围，并且不创建订单

#### Scenario: 单价精度过高或不是数字
- **WHEN** 用户使用超过两位小数或非数字文本作为单价尝试保存
- **THEN** MiniOrder 拒绝保存、提示所需的单价格式，并且不创建订单

### Requirement: 自动计算订单金额
当数量和单价均有效时，MiniOrder MUST（必须）使用十进制运算显示两者乘积，并将结果保留两位小数。

#### Scenario: 有效输入计算金额
- **WHEN** 用户输入数量 3 和单价 12.50
- **THEN** 只读订单金额显示 37.50

#### Scenario: 无效操作数清空金额
- **WHEN** 数量或单价任一字段为空或无效
- **THEN** 订单金额不显示任何计算结果

### Requirement: 保存有效订单
一次有效保存 MUST（必须）仅持久化一条订单，为其分配 `MO-yyyyMMdd-NNNN` 格式的唯一订单编号，将状态设置为“新建”，并使该订单可被查询。

#### Scenario: 保存成功
- **WHEN** 用户保存有效的客户、商品、数量和单价值
- **THEN** MiniOrder 确认保存成功，并为唯一一条新建订单显示生成的编号、计算金额和“新建”状态

#### Scenario: 连续保存产生唯一流水号
- **WHEN** 同一天保存两条有效订单
- **THEN** 两个编号均使用当天日期，且第二个四位流水号大于第一个

### Requirement: 查询订单
MiniOrder MUST（必须）列出已持久化的订单，支持使用关键字对订单编号、客户名称或商品名称进行不区分大小写的包含匹配，并支持可选的精确状态筛选。

#### Scenario: 按客户名称片段查询
- **WHEN** 用户使用已保存客户名称的子串进行查询
- **THEN** 显示所有匹配订单，并排除不匹配订单

#### Scenario: 按状态查询
- **WHEN** 用户选择“新建”状态筛选条件
- **THEN** 仅显示状态为“新建”的订单

#### Scenario: 没有匹配订单
- **WHEN** 没有已保存订单符合当前筛选条件
- **THEN** 结果列表为空，且 MiniOrder 提示找到 0 条订单

### Requirement: 显示完整订单信息
每条查询结果 MUST（必须）显示订单编号、客户、商品、数量、单价、订单金额、状态和创建时间。

#### Scenario: 已保存订单出现在结果中
- **WHEN** 当前查询结果包含一条已保存订单
- **THEN** 所有显示值均与保存时接受的值一致

### Requirement: 重启后保留订单
保存到当前测试数据目录的订单，在 MiniOrder 关闭并使用同一目录重启后 MUST（必须）仍然可用。

#### Scenario: 使用现有数据重启
- **WHEN** MiniOrder 使用包含已保存订单的测试数据目录重启
- **THEN** 该订单出现在查询结果中，且所有值保持不变
