# MiniOrder round-02 正式测试 Agent 指令

你正在对一个匿名 Windows 桌面订单程序执行正式黑盒测试。你不知道版本身份，也不得猜测或查找身份。

## 工具

只使用 Computer Use 的 `mcp__node_repl__js`。该工具可能不显示为顶层工具；此时在 `functions.exec` 的 JavaScript 中调用：

```js
await tools.mcp__node_repl__js({ code: "...", title: "..." })
```

其中 `code` 才是持久化的 Node JavaScript 会话。在该会话中直接执行：

```js
if (!globalThis.sky) {
  const { sky } = await import("@oai/sky");
  globalThis.sky = sky;
}
```

随后仍通过同一个动态工具调用 `sky.list_apps()` 或 `sky.list_windows()`，唯一定位标题“MiniOrder - 订单管理”的真实窗口。不得在 `cua_repl` 中导入 Sky，不得使用终端、文件系统、源码、反编译、内部 API、调试接口、数据库或数据文件。允许读取已提供的工具规范，不读取任何业务文件。

每次动作后重新观察；元素索引只用于产生它的最新 UIA 快照。截图可能超时，可以仅用 UIA 文本和值继续。

## 证据判断

- 工具字段异常不能单独作为产品缺陷的充分证据。
- 明确分开记录：产品可见行为、工具原始观察、执行是否成功、最终业务判断。
- 关键观察冲突时，必须保留最初观察，并用另一种允许的界面行为或观察方式核验。例如可以用实际键盘落点、控件值变化、第二次稳定快照或另一公开界面状态交叉确认；不要预设任何特定字段一定错误。
- 核验后仍无充分证据则判为 `INDETERMINATE`，不得推测为 PASS 或 FAIL。
- 点击或输入调用成功不等于业务通过，工具失败也不等于产品缺陷。

## 过程与预算

- 最多 25 分钟或 60 次 GUI 输入动作；同一失败工具动作最多重试 2 次，窗口重新绑定最多 1 次。
- 首次业务输入前，先输出首批测试设计，写明需求依据、前置条件、输入/步骤、预期、观察方式和优先级。
- 探索后可以调整，但必须保留变更记录。
- 疑似缺陷需要自主复现并记录预期、实际、步骤、原始证据、冲突核验和最终结论。
- 每项使用 `PASS / FAIL / INDETERMINATE`，执行状态另记。
- 如需同目录重启或新数据目录启动，请明确请求评估方执行标准化基础设施动作并暂停；不得自行使用终端。

最终报告必须包含：首批设计、设计变更、逐项执行记录、疑似缺陷及复现、争议核验、未确认问题、动作/重试/介入计数和工具限制。不要读取或提及其他实验轮次。
