# MiniOrder 第二轮 UIA 黑盒自主测试实验协议

冻结时间：2026-10-21（Asia/Shanghai），正式运行前

## 实验问题

在程序、需求、种子、预算和评分规则不变的情况下，加入正确工具入口、启动健康检查和通用争议证据核验规则后，新测试 Agent 能否再次自主发现业务缺陷，并更准确地区分产品异常、工具异常和证据不足。

## 相对 round-01 的变化

1. 明确只能在 `mcp__node_repl__js` 中直接导入 `@oai/sky`，不得在 `cua_repl` 中导入 Sky。若该工具不显示为顶层工具，通过 `functions.exec` 的 `tools.mcp__node_repl__js` 调用动态工具。
2. 正式运行前增加不计分的健康检查：初始化、唯一窗口观察、无业务副作用的页签往返和 UIA 回读。
3. 增加通用证据规则：工具字段异常不能单独证明产品缺陷；关键观察冲突时用另一种允许的 GUI 行为或观察交叉核验；仍不足则判为 `INDETERMINATE`。

MiniOrder 业务、中文需求、固定种子、正式预算和评分权重均未改变，因此两轮可以比较，但不能描述为流程完全相同的重复实验。

## 测试方可见输入与边界

- 中文业务需求全文、已启动的匿名 MiniOrder 窗口、正确工具使用规范和本协议中的通用证据规则。
- 允许 UIA 树、控件值、焦点、选中文本、标准键盘及允许的 GUI 行为；截图超时不阻塞 UIA 路径。
- 禁止终端、文件系统、源码、反编译、内部数据、数据库、调试接口、内部 API、上一轮报告、真值、版本身份和其他测试会话。

## 预算与恢复

- 每个正式目标最多 25 分钟或 60 次 GUI 输入动作，以先到者为准。
- 同一失败工具动作最多重试 2 次；窗口重新绑定最多 1 次。
- 评估方只执行运行前重置/启动、协议允许的同目录重启或新目录启动、运行后关闭；初始提示后的其他消息均计人工介入。
- 连续恢复失败、预算耗尽、关键计划完成或程序不可继续操作时结束。

## 测试与证据规则

1. 首次业务输入前输出首批设计：需求依据、前置、输入/步骤、预期、观察方式和优先级。
2. 探索后允许调整，但保留原设计和变更原因。
3. 每项分开记录产品可见行为、工具原始观察、执行状态和 `PASS / FAIL / INDETERMINATE`。
4. 动作调用成功不等于业务通过；工具失败不等于产品缺陷。
5. 疑似缺陷必须自主复现。工具字段与界面行为、多个工具字段或连续快照发生冲突时，使用第二种允许的 GUI 观察核验，并保留最初观察和核验步骤。
6. 无法取得充分证据时使用 `INDETERMINATE`，不得用推测补足。

## 固定评分

每目标 100 分：首批设计 20、可判定执行覆盖 25、证据与状态区分 20、结论正确性 20、缺陷复现或无缺陷判断 10、自主性 5。

六个固定需求组仍为：录入字段与初始状态、文本校验、数量/单价校验与金额、保存/编号/状态、查询筛选与完整显示、持久化与数据目录隔离。

## 报告锁定

三个正式报告原样保存并计算 SHA-256，全部锁定后才揭示私有映射评分。评估意见和争议裁决不得回写原始报告。
