# MiniOrder round-01 与 round-02 对比

| 指标 | round-01 | round-02 | 可支持的解释 |
|---|---:|---:|---|
| 正式目标完成率 | 3/3 | 3/3 | 两轮都完成三目标 |
| 已知缺陷检出 | 2/2 | 1/2 | 第二轮漏掉数量 0 缺陷，检出能力未稳定复现 |
| 产品误报 | 1 | 0 | 第二轮没有重复焦点误报 |
| 明确焦点冲突自主核验 | 0/1 | 2/2 | 新规则在两个实际触发目标中均被正确执行 |
| 评估方介入归属判断 | 1 | 0 | 第二轮争议由 Agent 自主解决 |
| 正式目标基础设施阻塞 | 两次早期尝试 | 0 | 正确入口避免了原错误通道，但截图限制仍在 |
| 测试项可判定率 | 26/33 正确可判定 | 40/52 可判定 | 用例拆分不同，不能直接视作可靠性提升 |

## 已有证据支持

- 正确工具入口规范避免了把错误 REPL 通道继续当作 Sky 全局服务故障。
- 通用争议规则没有屏蔽焦点测试；目标 02、03 都触发焦点字段冲突，并通过实际键盘落点或选中文本自主核验。
- 第二轮没有产品误报，也没有由评估方代替判断问题归属。

## 不能下的结论

- 不能宣布总体能力提高或稳定：round-02 已知缺陷检出从 `100%` 降为 `50%`。
- 不能把误报下降完全归因于提示修正：Codex 桌面包版本从 `26.1013.40934` 变为 `26.1013.4894.0`，正式上下文也从 projectless 线程变为 `fork_turns=none` Agent。
- 不能评价视觉路径：两轮截图均超时或不可用。
- 不能外推到其他 Windows C/S 软件、多 DPI、RDP 或无人值守环境。
