## MiniOrder 业务需求说明

### 1. 用途与范围

MiniOrder 是一个供单机用户录入和查询订单的 Windows 桌面程序。本说明只定义用户能够观察到的业务行为。

### 2. 新建订单

“新建订单”页面应提供以下字段：

- 客户名称：必填，去除首尾空格后长度为 1～50 个字符。
- 商品名称：必填，去除首尾空格后长度为 1～50 个字符。
- 数量：必填，必须是 1～999（含边界）的整数。
- 单价：必填，必须是 0.01～999999.99（含边界）的十进制金额，小数位不得超过两位。
- 订单金额：只读字段。

打开空白表单时，可编辑字段应为空，订单金额不得显示计算结果。当数量和单价均有效时，订单金额应实时显示“数量 × 单价”的结果并保留两位小数；任一操作数为空或无效时，金额应为空。

保存时，程序应检查全部字段。无效订单不得被保存，应指出无效字段，并把输入焦点移到第一个无效字段。一次有效保存只能新增一条订单。

### 3. 订单编号与状态

保存成功后，程序应显示成功信息，并为订单生成唯一编号。编号格式为 `MO-yyyyMMdd-NNNN`：日期部分使用保存当天的本地日期，四位流水号在同一天递增。

新保存订单的状态应为“新建”。

### 4. 查询订单

“查询订单”页面应列出已经保存的订单。查询条件包括：

- 可选关键字：对订单编号、客户名称或商品名称进行不区分大小写的包含匹配。
- 可选状态：对订单状态进行精确匹配。

两个条件同时设置时应同时生效。清除筛选后应恢复完整列表。没有匹配订单时，结果列表应为空，并显示“找到 0 条订单”。

每条结果应显示订单编号、客户名称、商品名称、数量、单价、订单金额、状态和创建时间。显示值应与保存时接受的值一致。

### 5. 持久化与运行限制

订单保存到本次运行指定的数据目录。程序关闭后，使用同一数据目录重新启动，应仍能查询到原有订单，且各字段值保持不变。不同数据目录中的订单不得相互出现。

程序完成上述流程不应依赖网络服务、外部设备、数据库服务器或管理员权限。
