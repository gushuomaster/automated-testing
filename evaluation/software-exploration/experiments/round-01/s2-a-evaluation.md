# S2-A 独立评估

## 结论

S2-A 正式运行完成且原始报告锁有效，但没有通过全部冻结门槛。失败项仅为 UI 相关需求映射召回率：`36/46 = 78.26%`，低于 90%。这不是工具阻塞或产品失败，而是测试 Agent 对允许动作边界过于保守，把 10 个已有入口或可见状态的需求写成 `UNREACHABLE`，没有按冻结真值保留为 `PARTIALLY_MAPPED`。

## 运行事实

- 输入角色：评估方核验需求集合；52 条需求、8 条歧义。
- 预算消耗：9 分钟、22 次 GUI 动作、1 次窗口重绑定、0 次人工介入。
- 工具恢复：截图超时后转为 UIA 文本路径；页签几何点击不可用后改用 `Control+Tab`。
- 安全性：结束时恢复空表单和完整查询状态；固定种子哈希不变；持久化副作用 0。
- 报告格式：合法 JSON，但严格 Schema 有 54 个错误，详见 `format-adjudication.md`。

## 漏映射与状态偏差

漏计入召回率的 10 条 UI 需求为：REQ-025～REQ-030、REQ-044、REQ-046～REQ-048。它们都包含禁止执行的保存、重启或数据目录动作，但冻结真值要求的是识别公开入口、既存状态或运行边界，并标为 `PARTIALLY_MAPPED`；协议没有要求执行这些风险动作。

另外，REQ-045 应为 `NOT_UI_OBSERVABLE`，报告写成 `UNREACHABLE`。REQ-010、REQ-012、REQ-023、REQ-032 则把部分证据写成完整 `MAPPED`；REQ-038、REQ-040 把真值完整映射写成部分映射。这些差异在精确状态一致率中保留，没有通过修改原报告来纠正。

## 能力判断

有证据支持 Agent 能自主发现两个关键入口、主要字段、金额联动、查询过滤和结果状态，并能在 UIA 限制下选择替代路径。但本轮不支持“在动作受限时稳定区分部分映射与不可达”的结论，因此 S2-A 判定为完成但未通过。
