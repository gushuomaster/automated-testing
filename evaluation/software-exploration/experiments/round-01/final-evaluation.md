## 分层结论

| 层次 | 状态 | 证据支持的结论 |
| --- | --- | --- |
| 样本与工具就绪 | 完成 | 冻结资产无漂移；独立健康检查完成真实窗口观察、页签往返和回读，数据未变化 |

原始报告均为合法 JSON，但不符合严格输出 Schema：S2-A 54 个错误，S2-B 53 个错误。格式问题不影响锁后人工评分，但意味着“严格结构化输出”尚未验证通过。

补充诊断中，状态分类可按真值逐项计算；工具分类准确率无法独立计分。原因是正式运行没有冻结逐次工具调用的独立日志，只保留了 Agent 在原始报告中的 `tool_status` 和限制说明。本轮只能确认报告内部没有把工具异常写成产品失败，不能据此声称工具分类准确率达到某个百分比，该项保留为 `INDETERMINATE`，且不进入冻结门槛。

## 主要发现

1. 两个独立 Agent 都能在截图和几何点击不可用时继续使用 UIA 文本、键盘和动作后回读，没有把工具失败写成产品缺陷。
2. 两轮的正式映射均由有效观察引用支持，没有无依据控件或错误 UI 映射；高精确率得到两次运行支持。
3. 主要失败不是找不到窗口或控件，而是分类策略。完整行为被安全边界禁止时，S2-A 尤其容易用 `UNREACHABLE` 覆盖已经找到的入口和状态，损失部分映射召回。
4. S2-B 的 S1 输入保持了全部 52 条需求语义，本轮未发现上游信息丢失。但 B 的成绩更高同时伴随更多动作和不同 Agent，不能做因果归因。
5. 两份报告相同的 Schema 错误暴露了实验提示传递问题，应在下一轮修正字段类型说明，而不是改写本轮答案。
6. S2-B 的 REQ-030、REQ-044 报告了保存后路径但没有执行证据；锁后按不可复现裁决。REQ-025～REQ-029 只声称安全前缀，逐条裁决后计入路径分子。
7. 工具异常分类只有原始报告自述，没有独立工具调用日志可复核；“未误判产品失败”有报告证据，但“工具分类准确率”未得到数值证据。

## 下一步最小建议

停止在 S2，不自动进入 S3。下一次最小动作应是一次新的 S2 校准轮：只修正通用提示中的两点，一是直接提供完整字段类型模板，二是用不含业务答案的定义说明“入口已发现但深层动作被禁止时应为 `PARTIALLY_MAPPED`，不是 `UNREACHABLE`”。使用新的独立上下文重复同一受控样本，验证召回稳定性；之后再选择此前未参与流程调整、具有合法需求和评估真值的第二个 Windows 软件验证泛化。

逐项裁决见 `adjudications/s2-a.json`、`adjudications/s2-b.json`；格式裁决、单轮评估和连接比较与本报告同目录保存。
