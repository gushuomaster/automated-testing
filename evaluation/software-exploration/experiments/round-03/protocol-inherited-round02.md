# S2 round-02 校准轮协议增补

本轮由用户同意后继续既有 S2 任务，属于 development/calibration。MiniOrder 已参与流程调整，不能将本轮称为新的跨软件泛化盲测。

## 输入与不变项

沿用 round-01 的两套 52 条需求输入、8 条歧义、评估真值、正确基线构建和固定种子，逐字节核对。S2-A 和 S2-B 各使用独立的新上下文与独立数据目录，按 A 后 B 的顺序执行；不互相提供结果。

保留 15 分钟或 30 次 GUI 输入动作、同一失败动作最多 2 次重试、最多 1 次窗口重绑定。保留入口召回 100%、UI 映射召回至少 90%、映射精确率与路径复现至少 95%、无依据控件不超过 5%、持久化副作用为 0 的门槛。不得看到成绩后更改。

## 相对 round-01 的变化

1. 每个测试上下文直接收到完整报告 Schema、完整工具文档与需求输入，不再仅引用 Schema 名称。明确 `confidence` 为 0～1 数字、`summary` 为字符串、各对象禁止额外属性。
2. 通用判定说明：已观察到相关入口或状态，但完整路径受动作边界限制时，应保留 `PARTIALLY_MAPPED`；`UNREACHABLE` 需要允许动作中的实际到达失败证据。不得仅因动作被禁止而称不可达。
3. 将已执行的安全路径与仅推导的后续路径写清楚；不得把未执行的后续状态声称为已经观察或复现。
4. 评估侧保留独立会话的逐次工具调用参数、返回内容、时间和最终答复，报告锁覆盖原始报告与日志。日志只由评估侧从本次会话记录提取，不通过新增 GUI 执行器实现。

每条正式映射（MAPPED 或 PARTIALLY_MAPPED）对应一个报告路径裁决；只声称安全前缀时按该层级复验，声称完整路径时必须有完整证据。路径分母为全部正式映射，不只选择成功项。这沿用 round-01 锁后操作口径，并在本次运行前明确，不能称两轮流程完全相同。

## 健康检查与工具版本

健康检查必须在独立诊断上下文完成初始化、唯一窗口观察、一次不修改业务数据的动作及回读，再核对种子。失败则不启动 A/B。

当前可用 computer-use 技能包为 26.1023.50603，round-01 记录为 26.1021.31345；本次没有主动安装、升级或更换执行器。应冻结实际文档并检查健康检查中的 API 与行为。尚不能确认实质工具行为相同时，不合并两轮成绩或把差异归因于提示修正。

## 锁定与评估

每个上下文在首次 GUI 输入前给出计划。结束时原样锁定报告和工具日志，随后才能评分。Schema 不合规也原样保留，新增格式裁决，不要求 Agent 重写答案。

工具分类准确率仅对独立日志中可验证的事件评分；没有足够日志时为 INDETERMINATE。产品行为、工具观察、执行状态与映射结论分开记录。工具异常不能独自证明产品问题。

不预注册必须获得的好成绩，不更换会话刷成绩。准备完成、工具恢复或健康检查通过均不等于 A/B 完成。
