# S2 软件探索受控实验协议

冻结对象：MiniOrder Baseline，UIA 文本路径

## 实验问题

1. S2-A：在输入为人工核验需求集合时，独立测试 Agent 能否找到陌生软件的功能入口、控件、可达状态和非破坏性路径，并建立有证据的需求映射？
2. S2-B：将输入替换为 S1 的真实 MiniOrder 需求基线后，上述能力和映射质量是否保持，连接处出现哪些丢失、扩大或额外成本？

本实验不评价测试用例设计、业务 PASS/FAIL、缺陷发现或持久化测试。

## 测试方可见输入

- 当前运行对应的需求输入包内容；
- 已启动的匿名 Windows 软件窗口；
- `computer-use` 技能、`mcp__node_repl__js + @oai/sky` 使用规范；
- 本协议的动作边界、预算、状态枚举和报告 Schema。

测试方不得读取文件系统、终端、源码、内部数据、评估真值、历史报告、缺陷清单、版本身份、其他运行输出或预写探索答案。

## 允许与禁止动作

允许：UIA 观察、控件属性读取、页签切换、焦点移动、组合框展开、标准键盘、不会保存的瞬时输入，以及结束前清除瞬时输入。

禁止：保存订单、删除或修改持久化数据、读取数据文件、运行缺陷触发用例、用内部 API 绕过 GUI、判断产品 PASS/FAIL、报告缺陷。

任何动作之后必须重新观察。旧 UIA 索引不得跨界面状态继续使用。动作调用成功不代表状态已经改变。

## 预算与恢复

- 每次正式运行最多 15 分钟或 30 次 GUI 输入动作，以先到者为准。
- 同一失败动作最多重试 2 次；窗口重新绑定最多 1 次。
- 工具初始化、被动观察不计 GUI 输入动作；页签、键盘、值设置和组合框选择计 1 次。
- 评估方只负责运行前重置/启动和运行后关闭。初始提示后的业务或路径提示均计人工介入。
- 连续恢复失败、预算耗尽、计划完成或出现副作用风险时结束。

## 映射状态

- `MAPPED`：有实际 GUI/UIA 证据支持入口、控件或非破坏性可达状态。
- `PARTIALLY_MAPPED`：只找到部分入口或路径；完整状态需要禁止的持久化动作、运行控制或额外证据。
- `NOT_UI_OBSERVABLE`：需求属于文档范围、外部环境或其他无法通过公开 GUI 观察的事项。
- `UNREACHABLE`：已发现理论入口，但在预算和允许动作内无法到达，并有失败轨迹。
- `INDETERMINATE`：工具或证据不足，无法判为以上状态。

找不到入口不能直接写成产品缺陷或功能不存在。软件实际显示的文字也不能反写为需求预期。

## 冻结指标与门槛

- 关键入口召回率：正确找到的关键入口 / 2，门槛 100%。
- UI 相关需求映射召回率：正确完整或部分映射 / 真值 UI 相关需求，门槛 90%。
- 映射精确率：有真值支持的正式映射 / Agent 报告的正式映射，门槛 95%。
- 路径可复现率：评估方可复现路径 / Agent 报告路径，门槛 95%。
- 无依据控件比例：不存在或无证据控件 / Agent 报告控件，上限 5%。
- 持久化副作用：0。

`NOT_UI_OBSERVABLE`、`UNREACHABLE` 和 `INDETERMINATE` 单列，不为了提高召回率强制归入映射。部分映射计入召回分子，但必须如实标记，不能计作完整映射。S2-A 与 S2-B 分别评分，不计算掩盖单轮失败的总平均分。

## 锁定与裁决

原始报告先按字节锁定，再由评估方读取真值逐项裁决。原始报告不得修改；解析修正、路径复验和评分写入单独文件。若输出无法解析，保留原始文本并将可判定部分人工转录到裁决文件，不能让 Agent 重写答案。
