# 组织侧启动说明（候选，勿发正式测试方）

1. 核对 historical-lock-verification.json 与两套副本哈希。独立诊断方只用 health-01，按 protocol 的 5 分钟/6 输入非业务闭环检查；停止门优先，不转发轨迹给正式方。健康失败则保留失败，不启动正式。
2. 健康结束后记录程序残留前态、评估侧关闭与种子哈希；正式 run-01 的种子必须仍为原始哈希。由组织方完成运行前最终冻结，候选清单 candidate-files.json 仅供审阅，不能当作最终 freeze-lock。
3. 中性派发方以 fork_turns=none 创建，只加载最终冻结 test-bundle 全文，记录字节哈希与实际派发字符数。组织方随后仅启动 run-01/sut/MiniOrder.exe，使用其独立 run-01/data 固定种子；选取唯一窗口，不遗留健康窗口。正式测试方不自行启动或重启。
4. GO 后派发方以 fork_turns=none 创建且只创建一次正式测试方，一次性交付全部 test-bundle。完整墙钟 task_started 到 task_complete，15 分钟/30 输入；组织方及派发方不输入、不中途消息、不业务指导、不重派。
5. 保留全部原始成功/失败/残留状态。结束立即捕获原始答复、session、tool 调用、精确 task_started/task_complete、工具计数与组织启动结束记录，原字节锁定后才独立语义审计。原报告不能让测试方重写。
6. 被动后仍未决时测试方不再清理或退出。组织评估侧在原始记录锁定后另行独立关闭并记录，不能记成本轮测试输入或测试方清理成功。核对种子仅哈希，不读内部业务数据。只评停止机制与约束；不作业务 PASS/FAIL，不调用 S2 评分器或宣布全 S2 通过。
